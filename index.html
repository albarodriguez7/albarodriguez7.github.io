    Ingeniería

    Cómo construyo agentes fiables

    Un agente que funciona en una demo no basta. Estas son decisiones que he tomado en mis propios proyectos para que el LLM sea útil sin fiarse de él a ciegas.

    01
    La IA extrae, el código decide
    El LLM solo hace lo que hace mejor que el código: entender texto desordenado. La puntuación y la decisión final son reglas en Python con 16 tests: coherentes, explicables y gratuitas.
    Agente de leads
    02
    Pruebas, no conclusiones
    En vez de preguntar «¿cuántas sedes tiene?», el agente debe copiar literalmente la frase o las direcciones de la web. Si no las encuentra, dice «no aparece» en lugar de deducirlo.
    Agente de leads
    03
    Los límites van en el código
    El límite de páginas no depende de que el modelo obedezca: al alcanzarlo, el código le retira las herramientas (tool_choice="none"). En reservas, el cliente identificado lo fija el código, no el modelo: un «cancela la cita del cliente 3» no tiene efecto.
    Ambos agentes
    04
    Medir antes de mejorar
    Dataset en LangSmith con 35 leads reales, cada respuesta respaldada por una cita de la web de la empresa, y 5 evaluadores separados. Revisando cada fallo en las trazas encontré 4 problemas reales del agente, los corregí y pasé del 90 % al 99 %, comparando experimentos en cada paso.
    Agente de leads
    05
    Datos consistentes
    Las reservas usan transacciones de SQLite con BEGIN IMMEDIATE para que dos clientes no se queden el mismo hueco. Google Calendar es un espejo: si Google falla, la reserva se guarda igual y se sincroniza después.
    Asistente de reservas
    06
    Sin fechas inventadas
    Un prompt dinámico inyecta en cada mensaje la fecha de Madrid y un calendario de 14 días, para que el modelo traduzca «el viernes» a una fecha real sin hacer cálculos.
    Asistente de reservas
    Proceso

    Cómo trabajo

    1. Caso de uso
    Entender la necesidad del negocio y qué tiene que resolver el asistente o el agente.
    2. Diseño del agente
    Elegir herramientas, fuentes de información (RAG), memoria y cómo se conecta con APIs y bases de datos.
    3. Prueba y evaluación
    Tests automatizados para la lógica determinista y datasets y trazas en LangSmith para medir las respuestas del agente.
    4. Interfaz y despliegue
    Interfaces en Streamlit y APIs con FastAPI, desplegadas en la nube.
    5. Documentación
    README con las decisiones técnicas y las limitaciones conocidas, para que el proyecto se pueda entender y seguir mejorando.
